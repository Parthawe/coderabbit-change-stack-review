[Open the editable Paper page](https://app.paper.design/file/01M5AQACJZP42ZGTRX7GF9ERE7/p-3-0). Start with “00 · Compare four product approaches.” The twelve full-size editable screens sit to its right, arranged in four rows.

Read each row left to right:

| Journey | Start | Inspect | Decide |
| --- | --- | --- | --- |
| A · Intended behavior | Frame an expectation | Attach a code excerpt and an evidence note | Keep the expectation open and prepare a review |
| B · Counterexamples | Choose a proposed sequence | Trace the reset handler | Record an inconclusive result and an evidence question |
| C · Impact outward | Choose the known layer dependency | Inspect the caller and missing utility boundary | Record coverage gaps and draft a source request |
| D · Author handoff | Start with missing author input | Show labeled illustrative input and its code links | Save an unsent reviewer question linked to reset code |

All screens use the same supplied coderabbitai/mono #22041 excerpt. The cache and reset code are transcribed from the supplied screenshot. Proposed expectations, scenarios, author input, and reviewer drafts are labeled. Missing code, tests, and author responses remain unknown.

These are static Paper walkthroughs, not four connected browser prototypes. Every frame identifies its transition and resulting state. No messages or reviews are sent.

The PNG exports are 1160 × 1000 each. `overview.png` compares all twelve states. `screen-source.json` preserves the authored HTML groups; `manifest.json` records the order and content boundaries. The Paper page contains the editable design nodes.
